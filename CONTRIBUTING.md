# Como contribuímos na Conecta

Este guia é o ponto de partida para qualquer repositório da organização. Regras específicas do projeto podem complementar — nunca reduzir — estes padrões.

## Antes de começar

1. Confirme o problema, o usuário afetado e o resultado esperado.
2. Abra ou associe uma issue com contexto e critérios de aceite.
3. Valide riscos de privacidade, segurança, acessibilidade e operação.
4. Prefira a menor mudança capaz de entregar valor completo.

## Fluxo de trabalho

1. Crie uma branch curta a partir de `main`.
2. Use nomes claros: `feat/`, `fix/`, `docs/`, `chore/` ou `security/`.
3. Faça commits coesos e mensagens objetivas.
4. Execute lint, testes e build localmente.
5. Abra um pull request usando o template da organização.
6. Responda às revisões e aguarde os checks obrigatórios.
7. Faça merge por squash e remova a branch.

## Definition of Done

- [ ] Critérios de aceite atendidos
- [ ] Testes cobrindo o comportamento relevante
- [ ] Documentação atualizada
- [ ] Sem segredos, dados pessoais ou informações de escolas
- [ ] Acessibilidade avaliada quando há interface
- [ ] Logs e métricas sem informações sensíveis
- [ ] Migração e rollback documentados quando aplicáveis
- [ ] Revisão técnica concluída

## Pull requests que ajudam o time

Explique **por que** a mudança existe, o que ficou diferente, como validar e quais riscos permanecem. Imagens e vídeos são bem-vindos para mudanças visuais, desde que não exponham dados reais.

Mudanças grandes devem ser quebradas em entregas menores ou precedidas por uma decisão técnica registrada.

## Segurança

Nunca publique vulnerabilidades em issues. Siga a [política de segurança](SECURITY.md) e avise imediatamente um proprietário da organização em caso de exposição.

## Conduta

Ao colaborar, siga nosso [Código de Conduta](CODE_OF_CONDUCT.md).
